# CLAUDE.md

Este archivo ofrece orientación a Claude Code (claude.ai/code) al trabajar con el código de este repositorio.

## Proyecto

"Arcade Vault" es una aplicación **Angular** (Angular 22, componentes standalone, signals, `@angular/build`). Todo el código nuevo debe ser Angular idiomático: componentes standalone con `templateUrl`, APIs de signals `input()`/`output()`/`viewChild()`, control de flujo `@for`/`@if`, `computed()` para estado derivado, y rutas en `src/app/app.routes.ts`. No introduzcas React, Next.js ni otros frameworks.

`resources/resources/templates/` contiene un prototipo React desechable (la referencia de diseño/comportamiento) y es **solo una fuente desde la que portar** — nunca lo extiendas ni importes de él. Ignora `resources/__MACOSX` (basura del zip). Su `styles.css` ya está portado a `src/styles.css` y es el tema global.

## Comandos

- `npm start` — servidor de desarrollo (`ng serve`)
- `npm run build` — build de producción
- `npm run watch` — build de desarrollo en modo watch
- `npm test` — tests unitarios vía `ng test` (Vitest + jsdom, no Karma/Jasmine). Archivo único: `npx ng test --include=src/app/library/library.spec.ts`; ejecución única: `npx ng test --watch=false`
- `npm run lint` — ESLint (config plana `eslint.config.js`: `@eslint/js` + `typescript-eslint` `recommended`/`stylistic` + `angular-eslint`; prefijo de selector de componentes `app`/kebab-case, prefijo de directivas `app`/camelCase; reglas de accesibilidad (a11y) de plantillas en `.html`)
- Formato: Prettier (`printWidth` 100, comillas simples, parser de Angular para `.html`)
- **Hook de auto-formato** — `.claude/hooks/format-file.mjs` corre en cada `Write`/`Edit` (`PostToolUse`, configurado en `.claude/settings.local.json`): Prettier `--write`, luego ESLint `--fix` en TS/JS, y por último **elimina las líneas en blanco** del código (TS/JS/HTML/CSS/JSON — nunca en Markdown/YAML, nunca dentro de template literals). Por eso los archivos fuente **no tienen líneas en blanco entre bloques**; respeta ese estilo compacto al editar. El hook nunca bloquea (siempre `exit 0`).

## Skills (`.claude/skills/`, incluidas y versionadas en el repo)

- **frontend-design** + **ui-ux-pro-max** — Usa siempre frontend-design junto con ui-ux-pro-max para realizar la interfaz de usuario, pónganse de acuerdo para que no se genere conflicto entre las dos. En la práctica: focus visible, suficiente contraste, respetar `prefers-reduced-motion` (atenúa la decoración, nunca la jugabilidad), SVG/íconos decorativos `aria-hidden`.
- **spec** (`/spec <descripción>`) — diseñador guiado de specs: 4 fases (contexto → preguntas en bloques de 3–5 con `AskUserQuestion` → redactar → guardar). Escribe `specs/NN-slug.md` en estado **`Borrador`** y siembra `specs/.spec-config.yml` si falta. **No escribe código.**
- **spec-impl** (`/spec-impl NN-slug`) — implementa un spec cuyo estado signifique **Aprobado** (se bloquea si es `Borrador`/`En revisión`/`Implementado`/…). Crea y cambia a la rama `spec-NN-slug` (según `AutoCreateBranch` en `specs/.spec-config.yml`, por defecto `true`), muestra objetivo/alcance/plan/criterios, e implementa **paso a paso con pausas** para revisar el diff. **Nunca hace commit por su cuenta.**
- **add-game** (`/add-game <juego>`) — especialización de `/spec` que produce el spec de un **juego real** nuevo siguiendo la receta `add-game/references/receta-arcade.md` destilada de SPEC 05/06: motor TS agnóstico + componente dedicado + ruta `jugar/<id>` **antes** de `jugar/:id` + alta del catálogo **vía MCP de Supabase** (`UPDATE`/`INSERT` en `public.games`, no SQL versionado) + leaderboard por `game_id` + portada CSS `cover-<id>` + tests. Produce **sólo** el `.md` del spec, listo para `/spec-impl`; reutiliza la capa genérica (`SupabaseService`/`GamesService`/`ScoresService`/`GameCard`/`HallOfFame`), no la reescribe.

**Flujo spec-driven:** cada feature grande nace como spec numerado en `specs/` (`01`…`09`), se revisa y se aprueba a mano (`Borrador` → `Aprobado`), se implementa con `/spec-impl` en su rama `spec-NN-slug`, y al terminar se marca `Implementado`. Los juegos reales (SPEC 05/07/08/09) salieron de este flujo vía `/add-game` + `/spec-impl`.

Los demás juegos conservan el `GamePlayer` simulado (su propio botón de guardado también escribe en `scores`).
- `games/caida/` — segundo juego **real** (SPEC 07), un port de Tetris, ruta `jugar/caida` (declarada **antes** de `jugar/:id`). `caida-engine.ts` es un port TS **procedural** y agnóstico de framework de `references/started-games/03-tetris/game.js` con la **misma API pública que `AsteroidsEngine`** (`start`/`pause`/`resume`/`restart`/`destroy`/`setInput`/`getState`/`onState`, más `setBoardTheme`): tablero 10×20, las 8 piezas incl. la "tuerca" (índice 8) con los colores originales, `rotateCW`/`tryRotate` con wall-kicks `[0,−1,1,−2,2]`, `collide`/`clearLines`/ghost/`hardDrop`/`softDrop`, `LINE_SCORES`×nivel, nivel/velocidad cada 10 líneas. Canvas responsivo (relación 1:2, backing store DPR en `resize`/`ResizeObserver`); `update(dt)` no toca `ctx` para que las reglas se testeen unitariamente sin `getContext`. **Una sola vida**: `CaidaPhase` es `'playing' | 'gameover'` (sin `dead`). El motor dibuja EN PAUSA/GAME OVER en el canvas y la vista previa NEXT en un 2.º canvas; ESPACIO es hard-drop en juego / reinicio en game over. El componente `Caida` (standalone, signals) aloja ambos `<canvas>`, crea el motor solo en el navegador (`afterNextRender`, fuera de la zona de Angular), lo destruye en `ngOnDestroy`, refleja `onState` en el HUD neón del DOM (SCORE/LÍNEAS/NIVEL), dispara la pausa él mismo (P/Esc + botón — el motor **no** bindea P), añade 5 controles táctiles (←, →, rotar, soft, hard), un toggle de tema claro/oscuro solo del tablero persistido en `localStorage` (`av_caida_theme`, solo en navegador), y un botón aparte "GUARDAR PUNTUACIÓN" → `ScoresService.save({ game: 'caida', … })`.

El componente `BloqueBuster` (standalone, signals) aloja el `<canvas>`, crea el motor solo en el navegador (`afterNextRender`, fuera de la zona de Angular), lo destruye en `ngOnDestroy`, refleja `onState` en el HUD neón del DOM (SCORE/VIDAS/NIVEL), dispara la pausa él mismo (P/Esc + botón — el motor **no** bindea P), controles = ←/→ del teclado + arrastre con puntero sobre el canvas + 2 botones táctiles (←/→), un botón de silencio, y un botón aparte "GUARDAR PUNTUACIÓN" → `ScoresService.save({ game: 'bloque-buster', … })` mostrado en `gameover` **y** `win`.
- `games/snake/` — cuarto juego **real** (SPEC 09), un Snake **desde cero** (**no** hay referencia `game.js` — solo `references/started-games/05-snake-assets/` con `fruits.png` + `sprites.js`), ruta `jugar/snake` (declarada **antes** de `jugar/:id`). `snake-engine.ts` es agnóstico de framework y **procedural** con la **misma API pública que los demás motores** (`start`/`pause`/`resume`/`restart`/`destroy`/`setInput`/`getState`/`onState`): tablero cuadrado `GRID` 21×21, serpiente como `Cell[]`, movimiento **por tick** mediante un acumulador, bloqueo de reversa 180°, **wrap toroidal** (los muros no matan), fruta aleatoria en una celda libre con **puntos por fruta** (`FRUIT_POINTS`, niveles 10/20/30), +1 de crecimiento por bocado, aceleración (`stepInterval = max(60, 140 − 4·fruitsEaten)`). **Una sola vida**: `SnakePhase` es `'playing' | 'gameover'` (la auto-colisión la termina); ESPACIO reinicia. SPEC 09 añadió el cuarto juego **real**, **Snake** (`games/snake/`), construido **desde cero** (sin referencia `game.js` — solo los assets `fruits.png` + `sprites.js`) reutilizando el patrón de SPEC 05/07 (motor TS procedural aislado + componente dedicado + ruta propia + guardado en el Salón). A diferencia de SPEC 07/08, **creó una nueva fila de catálogo vía `INSERT`** (no `UPDATE`): **eliminó** el placeholder `serpentina` e insertó `snake` (ARCADE, `cover-snake`, `green`, `best` 0 / `plays` "—", `playable: true`, posición 3). También **limpió el catálogo**: los cinco placeholders no implementados restantes (`gloton`, `invasores`, `rocas`, `ranaria`, `duelo-pixel`) fueron **eliminados** de la tabla `games` y de la semilla de `games.data.ts` + `GAMES_FIXTURE`, dejando exactamente los 4 juegos implementados. Esto fija la convención de aquí en adelante: **cada juego se crea en la BD cuando se implementa** (no más placeholders sembrados). Snake come sprites de fruta de `fruits.png` en una grilla toroidal con una sola vida; sonido, obstáculos, niveles, power-ups y el recolor neón de las frutas quedan para specs futuras.

SPEC 10 añadió una **capa de jugabilidad móvil táctil** transversal, **sin tocar motores, jugabilidad, servicios ni BD**. **Solo en móvil** (media query `(hover: none) and (pointer: coarse), (max-width: 760px)`) la pantalla de juego de los 4 juegos se reapila en columna [HUD compacto] → [canvas] → **mando unificado** → **barra de pie**, con la altura del CRT acotada en `dvh` y safe-area (`viewport-fit=cover` en `index.html` + tokens `--sai-*` en `:root`). El **mando** (`.av-mobile-pad` → `.pad-dpad`/`.pad-actions`, reutilizando `.touch-btn`) es igual en los 4 juegos pero cada uno muestra **solo lo que usa**: Asteroides ←→↑ + FUEGO; Caída ←→↓ + ROTAR + CAÍDA; Bloque Buster ←→ (`.solo`, el arrastre sobre el canvas sigue intacto); Snake cruceta completa (`.solo`). La **barra de pie** (`.av-mobile-bar`) recoge PAUSA/SALIR/SKIN (+ SONIDO en Bloque Buster), que en móvil se ocultan del HUD de arriba (`.hud-actions`). Nuevo método `restartGame()` por componente + botón **«JUGAR DE NUEVO»** (`.av-restart`) en el panel de fin → `engine.restart()`; el texto «PULSA ESPACIO» se oculta en móvil. En **escritorio nada cambia** (todo nace `display: none` y solo se muestra en la media query). Se **eliminó** el viejo marcado/estilos `.touch-controls`/`.touch-cluster`/`.touch-dpad` (sustituidos por el mando; `.touch-btn` se conserva) y se añadió un suelo táctil `min-height: 44px` (solo móvil). Verificación en **dispositivo real**; landscape dedicado, bloqueo de orientación, PWA/háptica y un componente `GamePad` compartido quedan para futuros specs.

SPEC 11 reestilizó **solo la apariencia** del mando móvil de SPEC 10 para que parezca el gamepad neón **MK-II** (referencia `references/started-games/gamepad-assets/`), **sin tocar jugabilidad, motores, servicios, BD ni el escritorio** y **sin carcasa exterior**. Todo vive bajo la **misma media query móvil** de SPEC 10 (el mando sigue `display:none` en escritorio). La **cruceta** `.pad-dpad` pasó de glifos Unicode a **teclas con relieve 3D + flecha SVG** (`.pad-arrow`, `aria-hidden`) que al pulsar se hunden y encienden en cian, con un **hub central** `.pad-hub` + gema LED `.pad-hub-gem` (decorativa; latido detenido por `prefers-reduced-motion`). Los botones de acción pasaron a **círculos biselados `.pad-ab`** (`.pad-ab-ring` + `.pad-ab-letter`): **`.a` = magenta** (acción primaria) / **`.b` = cian** (secundaria) — identidad del PNG que **reemplaza** el viejo acento `.fire` del mando; la letra «A»/«B» es visible y la función va en `aria-label`/`title` (Asteroides A=FUEGO; Caída A=ROTAR, B=CAÍDA; Snake y Bloque Buster **sin** botones de acción, cruceta centrada `.solo`). Tamaños **fluidos con `clamp()`** (teclas/hub ≥44px táctil) y el `max-height` del canvas móvil afinado **48 → 46dvh** para que canvas + mando + barra de pie quepan sin scroll en 4:3 / 1:2 (Caída) / 1:1 (Snake). Reutiliza los `press()` existentes (sin vocabulario nuevo de `setInput`). El gabinete/carcasa exterior MK-II, skins del mando y un componente `GamePad` compartido quedan para futuros specs.

Comportamiento del prototipo a preservar al portar: las rutas eran `{name, id?}` en el hash de la URL (`biblioteca` | `detalle` | `player` | `auth` | `salon`) → mapéalas a rutas de Angular. El usuario con sesión iniciada aún persiste en `localStorage` (`av_user`); las puntuaciones ahora viven en la tabla `scores` de Supabase (la vieja clave de localStorage `av_scores` quedó retirada).
