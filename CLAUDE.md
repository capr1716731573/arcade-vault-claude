# CLAUDE.md

Este archivo ofrece orientación a Claude Code (claude.ai/code) al trabajar con el código de este repositorio.

## Proyecto

"Arcade Vault" es una aplicación **Angular** (Angular 22, componentes standalone, signals, `@angular/build`). Todo el código nuevo debe ser Angular idiomático: componentes standalone con `templateUrl`, APIs de signals `input()`/`output()`/`viewChild()`, control de flujo `@for`/`@if`, `computed()` para estado derivado, y rutas en `src/app/app.routes.ts`. No introduzcas React, Next.js ni otros frameworks.

`resources/resources/templates/` contiene un prototipo React desechable (la referencia de diseño/comportamiento) y es **solo una fuente desde la que portar** — nunca lo extiendas ni importes de él. Ignora `resources/__MACOSX` (basura del zip). Su `styles.css` ya está portado a `src/styles.css` y es el tema global.

## Comandos

- `npm start` — servidor de desarrollo (`ng serve`)
- `npm run build` — build de producción
- `npm run watch` — build de desarrollo en modo watch
- `npm test` — tests unitarios vía `ng test` (Vitest + jsdom, no Karma/Jasmine). Archivo único: `npx ng test --include=src/app/library/library.spec.ts`; ejecución única: `npx ng test --watch=false`
- `npm run lint` — ESLint (config plana `eslint.config.js`: `@eslint/js` + `typescript-eslint` `recommended`/`stylistic` + `angular-eslint`; prefijo de selector de componentes `app`/kebab-case, prefijo de directivas `app`/camelCase; reglas de accesibilidad (a11y) de plantillas en `.html`)
- Formato: Prettier (`printWidth` 100, comillas simples, parser de Angular para `.html`)
- **Hook de auto-formato** — `.claude/hooks/format-file.mjs` corre en cada `Write`/`Edit` (`PostToolUse`, configurado en `.claude/settings.local.json`): Prettier `--write`, luego ESLint `--fix` en TS/JS, y por último **elimina las líneas en blanco** del código (TS/JS/HTML/CSS/JSON — nunca en Markdown/YAML, nunca dentro de template literals). Por eso los archivos fuente **no tienen líneas en blanco entre bloques**; respeta ese estilo compacto al editar. El hook nunca bloquea (siempre `exit 0`).

## Skills (`.claude/skills/`, incluidas y versionadas en el repo)

- **frontend-design** + **ui-ux-pro-max** — Usa siempre frontend-design junto con ui-ux-pro-max para realizar la interfaz de usuario, pónganse de acuerdo para que no se genere conflicto entre las dos. En la práctica: focus visible, suficiente contraste, respetar `prefers-reduced-motion` (atenúa la decoración, nunca la jugabilidad), SVG/íconos decorativos `aria-hidden`.
- **spec** (`/spec <descripción>`) — diseñador guiado de specs: 4 fases (contexto → preguntas en bloques de 3–5 con `AskUserQuestion` → redactar → guardar). Escribe `specs/NN-slug.md` en estado **`Borrador`** y siembra `specs/.spec-config.yml` si falta. **No escribe código.**
- **spec-impl** (`/spec-impl NN-slug`) — implementa un spec cuyo estado signifique **Aprobado** (se bloquea si es `Borrador`/`En revisión`/`Implementado`/…). Crea y cambia a la rama `spec-NN-slug` (según `AutoCreateBranch` en `specs/.spec-config.yml`, por defecto `true`), muestra objetivo/alcance/plan/criterios, e implementa **paso a paso con pausas** para revisar el diff. **Nunca hace commit por su cuenta.**
- **spec-impl-game** (`/spec-impl-game NN-slug`) — especialización de `/spec-impl` para juegos: reutiliza sus 4 fases **leyéndolo en runtime** (mismo patrón que `/add-game`↔`/spec`) e implementa el spec igual. Al completar el **último paso** confirma una vez y dispara **en secuencia, nunca en paralelo**, primero el agente `@skin-designer <id>` y, **solo cuando termina**, `@mobile-porter <id>` sobre ese mismo juego. Deriva el `id` del juego (fila de catálogo / `src/app/games/<id>/` / ruta `jugar/<id>`); si el spec no es de un juego, omite esa fase. **Nunca hace commit** (ni él ni los agentes).
- **add-game** (`/add-game <juego>`) — especialización de `/spec` que produce el spec de un **juego real** nuevo siguiendo la receta `add-game/references/receta-arcade.md` destilada de SPEC 05/06: motor TS agnóstico + componente dedicado + ruta `jugar/<id>` **antes** de `jugar/:id` + alta del catálogo **vía MCP de Supabase** (`UPDATE`/`INSERT` en `public.games`, no SQL versionado) + leaderboard por `game_id` + portada CSS `cover-<id>` + tests. Produce **sólo** el `.md` del spec, listo para `/spec-impl`; reutiliza la capa genérica (`SupabaseService`/`GamesService`/`ScoresService`/`GameCard`/`HallOfFame`), no la reescribe.

**Flujo spec-driven:** cada feature grande nace como spec numerado en `specs/` (`01`…`14`), se revisa y se aprueba a mano (`Borrador` → `Aprobado`), se implementa con `/spec-impl` en su rama `spec-NN-slug`, y al terminar se marca `Implementado`. Los juegos reales (SPEC 05/07/08/09/12) salieron de este flujo vía `/add-game` + `/spec-impl`.

## Estado del porte (prototipo → Angular)

El prototipo React (`resources/resources/templates/`) está **100% portado** (biblioteca, home, acerca-de + contacto, navbar); nada pendiente. El resto del proyecto crece **spec-driven**: cada feature es un spec numerado `NN-slug.md` en `specs/` (hoy `01`…`16`) + los game-jams en `specs/game-jam/`, cada uno con su objetivo/alcance/plan/criterios/estado. **Para el detalle y la historia de una feature, consulta su spec en `specs/`** — no se reproducen aquí para no inflar este archivo.

Convenciones transversales que fija ese historial (no evidentes solo leyendo el código):

- **SSR + email** (SPEC 03): servidor Angular (`src/server.ts`) para `POST /api/contacto` vía Resend; la clave vive en `process.env.API_KEY_RESEND`, nunca en el bundle; páginas en `RenderMode.Client`.
- **5 juegos reales** (SPEC 05/07/08/09/12 — asteroides, caída, bloque-buster, snake, frogger): cada uno = motor TS agnóstico de framework + componente dedicado + ruta `jugar/<id>` **antes** de `jugar/:id` + guardado en el Salón (ver sus bullets en «Arquitectura»). El resto de entradas usa el `GamePlayer` simulado + insignia "PRÓXIMAMENTE".
- **Catálogo + leaderboard en Supabase** (SPEC 06): viven en las tablas `games`/`scores` con RLS; **cada juego se crea en la BD cuando se implementa** (desde SPEC 09, sin placeholders sembrados).
- **Capa móvil** (SPEC 10/11): jugabilidad táctil + mando neón MK-II, **solo** bajo la media query móvil; el escritorio no cambia.
- **Rendimiento** (SPEC 13, *Aprobado — en curso*): optimización del camino caliente de los motores + clase base `GameEngine` (pendiente de su `/spec-impl`); la parte de rendimiento la aplica `@game-performance-booster` de un juego a la vez.
- **Toda implementación es Angular**: un spec que llegue en otro framework se reescribe antes (SPEC 12).
- **Seguridad base** (SPEC 16): 6 headers de seguridad en `src/server.ts` (middleware Express como primer `app.use`, antes de `express.static`/SSR: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, HSTS `max-age=31536000; includeSubDomains`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`, `X-DNS-Prefetch-Control: off`; **CSP diferida** a su propio spec). `guestGuard` (`src/app/services/auth.guard.ts`) en `/acceso`, `/acceso/recuperar`, `/acceso/nueva-clave` (autenticado → `/cuenta`); `/acceso/callback` **sin** guard; `authGuard` sigue en `/cuenta`; **modo invitado intacto** (jugar sigue libre). Política de contraseña en cliente (`src/app/auth/password-policy.ts` — `PASSWORD_RE` ≥8 + minúscula + MAYÚSCULA + dígito + símbolo, espejo del panel, aplicada en el alta de `auth.ts` y en `nueva-clave.ts` antes de llamar a Supabase). `revoke execute on function public.rls_auto_enable()` a anon/authenticated/public (cierra los 2 lints `*_security_definer_function_executable` del advisor; vía MCP, **no versionado**, sin cambios de esquema). RLS ya habilitada en `games`/`scores`/`profiles` (verificado). Config del panel (min length/requirements/leaked-password/rate limit de signups) = **prerrequisito manual** (no programable por MCP). **Fuera:** CSP, CAPTCHA, gate global/login para jugar, recovery-guard estricto.

Al portar, preservar: la sesión la gestiona **Supabase Auth** (SPEC 14 — `supabase-js` persiste el token en `localStorage` solo en navegador; la vieja clave `av_user` y el `SessionService` falso quedaron retirados); las puntuaciones viven en la tabla `scores` de Supabase (la vieja clave `av_scores` quedó retirada).
